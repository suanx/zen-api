实测记录
  • 伪装完整客户端头 + bash/read 工具 + 强制流式 → 仍返回 FreeTierError
  • 非流式、不带工具 → 同样 FreeTierError
  • 完全不带伪装头 → 仍是 FreeTierError
  • 带真实 Key 的付费模型 → 鉴权通过，正常返回
  • /v1/models 匿名可读，说明网关本身与出网链路正常

结论：上游已在校验真实客户端身份，不再只看请求头。本项目的价值因此转向「用自己的域名统一入口 + 协议转换 + 鉴权管控」， 免费档能否恢复取决于上游政策，不是本地能改的。

它解决什么

免费档失效之后，网关本身的价值依然成立。

三套协议一个入口

OpenAI /chat/completions、Anthropic /messages、Responses /responses 统一走同一套鉴权与改写逻辑，客户端不用各自适配。

流式折叠

客户端要非流式时，网关把上游 SSE 折回完整 JSON，并按协议还原 tool_calls / tool_use / function_call，Agent 场景不会拿到自相矛盾的响应。

fail-closed 鉴权

配了服务端 Key 却没配 ACCESS_TOKEN 时一律 503 且不调用上游。失败是显式的，不会静默把付费额度敞给全网。

不泄露诊断信息

付费模式、伪装开关、重试轨迹默认都不返回。需要排查时设 DEBUG=1 才有 x-zen-* 头。

工具补齐不破坏原有

免费档要求请求体带 bash / read。网关按协议形状补齐缺失项而不是整段替换，客户端自带工具不受影响。

单一实现

三个路由共享同一份核心代码，改一处即全部生效。不会再出现「改了一个路由忘了另外两个」。

一次请求怎么走

从收到请求到返回，最多两次上游尝试。

1
fail-closed 鉴权 配了服务端 Key 就必须校验 ACCESS_TOKEN，缺失直接 503，不打上游
2
路径映射 /api/* 剥前缀后统一映射到 opencode.ai/zen，query 原样保留
3
按模型决定是否伪装 识别 free / big-pickle，注入对应协议的 bash+read 工具，必要时强制流式
4
鉴权分流重试 免费档优先匿名，付费档直接带 Key —— 每个付费请求只打一次上游
5
按协议折叠回传 客户端要非流式就把 SSE 折成对应 schema；模型列表只保留免费档

接入

任何支持 OpenAI 兼容配置的客户端都能直接用。

# OpenAI SDK
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "BASE/api/zen/v1",
  apiKey: "你的 Key",
});

const r = await client.chat.completions.create({
  model: "gpt-5.4",
  messages: [{ role: "user", content: "hi" }],
  stream: true,
});
# Anthropic SDK
base_url = "BASE/api/anthropic"
api_key  = "<ACCESS_TOKEN 或你的 Key>"
# curl 验证
curl BASE/api/zen/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.4","messages":[{"role":"user","content":"hi"}],"stream":true}'

部署要点

最容易踩的几条，完整步骤见仓库 README。

三条硬性要求
  • 函数地域必须选境外 —— opencode.ai 是境外域名，函数跑在大陆地域出网基本超时，选 ap-hongkong
  • 加速区域选「不含中国大陆」 —— 免备案，代价是国内访问走跨境节点
  • 绑自己的域名 —— 平台送的默认域名在大陆只能走 3 小时预览链接
别做成公共服务
  • 所有请求共用函数出口 IP，上游按 IP 限流，开放必撞
  • ACCESS_TOKEN 不配置时代码拒绝所有请求，这是防裸奔的，别改
  • 免费版出网仅 5 GB/月，比调用次数限制更紧
